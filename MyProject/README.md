# Project

This is a Razor Pages / ASP.NET Core web application (Razor Pages-style controllers and views) implemented with .NET 9 and C# 13.

The app manages banks, financial reports, regulatory circulars and includes role-based access control.

## Prerequisites

- .NET SDK 9 (install from https://dotnet.microsoft.com/) compatible with C# 13
- (Optional) `dotnet-ef` CLI if you need to run or update Entity Framework Core migrations:
  - Install: `dotnet tool install --global dotnet-ef`
- A SQL database (the app uses a connection string defined in `appsettings.json`).

## Build and run

1. Open a terminal and change directory to the project folder that contains the `.csproj` file. Example:

   ```bash
   cd Project
   ```

2. Restore and build:

   ```bash
   dotnet restore
   dotnet build
   ```

3. If you use EF Core migrations, apply them to your database (update connection string in `appsettings.json` first):

   ```bash
   # from the project folder that contains the .csproj
   dotnet ef database update
   ```

4. Run the app:

   ```bash
   dotnet run
   ```

5. Open the browser at the URL printed in the console (usually `https://localhost:5001` or `http://localhost:5000`).

## Seed data and roles

This project contains services that seed initial roles and data. By default the seeding code lives under `Services` and `Data`. If the seeder is wired up in `Program.cs` it will run at startup and create required roles and sample data (admins, roles, sample banks, etc.). Ensure the database is migrated/created before running the app.

## Project structure (main folders and files)

- `Program.cs` - Application entry point, service registration and middleware pipeline.
- `appsettings.json` - Application configuration (connection strings, logging, etc.).
- `Data/` - Database related classes
  - `ApplicationDbContext.cs` - EF Core DbContext and DbSet definitions for models.
  - `SeedData.cs`, `SendData.cs` - helpers for seeding and data sending.
- `Migrations/` - EF Core migration files generated by the project.
- `Models/` - Domain models used by the app
  - `Bank.cs` - bank entity and metadata
  - `FinancialReport.cs` - financial report entity
  - `ApplicationUser.cs` - identity user extension
  - `AuditLog.cs` - audit logging model
  - `RegulatoryCircular.cs` - regulatory circular model
- `ViewModel/` - view models used for pages and form binding
  - `FinancialReportViewModel.cs`
  - `BankViewModel.cs`
  - `RegulatoryCircularViewModels.cs`
- `Controllers/` - MVC controllers and Razor Pages controllers that implement application logic
  - `FinancialReportController.cs` - user-facing financial report flow
  - `AdminFinancialReportController.cs` - administrative review and approval of reports
  - `BankController.cs` - bank CRUD and management
  - `RegulatoryCircularController.cs` - regulatory circular management
  - `PublicBankController.cs` - registration flow for public banks
  - `HomeController.cs` - landing pages and privacy
- `Views/` - Razor views for controllers
  - `Views/FinancialReport/` - `Index.cshtml`, `Create.cshtml`, `Details.cshtml`
  - `Views/AdminFinancialReport/` - administrative views
  - `Views/Bank/` - bank management views
  - `Views/RegulatoryCircular/` - regulatory circular views
  - `Views/Shared/` - shared layout and partials (`_Layout.cshtml`, `_LoginPartial.cshtml`, `Error.cshtml`)
- `Areas/Identity/Pages/` - Identity Razor Pages for authentication (login, register, logout pages)
- `Services/` - application services
  - `RoleInitializer.cs` - ensures required roles exist
  - `DataSeeder.cs` - seeds sample data
  - `AuditService.cs` - records audit logs
- `Interfaces/` - service interfaces (e.g. `IAuditService.cs`)

## Important files to check before running

- `appsettings.json` - update `ConnectionStrings:DefaultConnection` to point to your database.
- `Program.cs` - confirm seeders or initializers are enabled only when desired.

## Common commands

- Build: `dotnet build`
- Run: `dotnet run`
- Run migrations: `dotnet ef migrations add <Name>` then `dotnet ef database update`
- Run tests: (if tests exist) `dotnet test`

## Notes

- The application uses ASP.NET Core Identity for authentication and role-based authorization. Create or seed at least one user with the `CommercialBankUser` role to access bank/financial-report functionality.
- The project includes simple CSV and PDF export endpoints under `FinancialReportController` for user reports.
